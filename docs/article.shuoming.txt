现在请协助我实现一套完全基于前端运行时的、模块化的 Markdown 文章系统。这套系统不依赖任何后端数据库或构建脚本，纯靠前端 JavaScript 解析 URL 参数、异步抓取指定目录的 Markdown 文件及局部 JSON 清单，并在运行时动态渲染输出。
请严格按照以下设计规范，输出代码：
### 1.物理目录与资产结构
系统资产存放在根目录的 `/doc` 文件夹下，组织架构严格定义如下：
- `/doc/update/`：存放 `recent.json`（最近更新）和 `recommend.json`（推荐内容）。用于首页极速加载和手动维护。
- `/doc/nb_[NotebookName]/`：以笔记本为单位的目录（例如 `/doc/nb_AtmoDyn/`）。
  - 内部包含一个单本笔记本的 `index.json`（用于生成该笔记本的左侧目录导航）。
  - 包含多个独立的文章文件夹（例如 `/lecture_01/`），每个文件夹内聚合存放 `note.md` 及其所需的图片/媒体资源。
- `/doc/publication/`：存放独立学术成果的 `.md` 文件。
- `/doc/recommend/`：存放特定推荐内容的 `.md` 文件。

### 2.文章加载引擎：`/article.html`
这是全站唯一的文章渲染入口。当访问 `/article.html?path=...` 时（例如 `?path=/doc/nb_AtmoDyn/lecture_01/note.md`），JavaScript 引擎需要执行以下流水线任务：

#### 任务A：正文异步抓取与 Markdown 渲染
1.根据 `path` 路径，使用 Fetch API 异步抓取原始 `.md` 文本。
2.使用 Markdown 解析器（如 Marked 或 Markdown-it）将其转化为 HTML，并渲染到页面的中央主体区域。
3.文章支持latex代码渲染。

#### 任务B：图片与资源的相对路径
- 由于 `note.md` 内部引用的图片通常写为相对路径（如 `![](image.png)` 或 `![](./image.png)`），当被 `/article.html` 动态加载后会因基准路径改变而破损。
- 解析器渲染完毕后，JS 必须立刻捕获中央区域内的所有 `<img>` 标签，自动提取当前 `note.md` 所在的绝对物理目录（例如 `/doc/nb_AtmoDyn/lecture_01/`），并将该前缀补全到图片的 `src` 属性中，实现图片原地复活。

#### 任务C：上下文感知与左侧目录（Notebook ToC）
- 引擎需要通过检测 URL 的 `path` 参数来识别当前文章的身份：
  - 如果路径中【不包含】`nb_` 关键字（如来自 `publication` 或 `recommend`）：视为独立文章，利用 CSS 机制将左侧隐藏。
  - 如果路径中【包含】`nb_` 关键字：解析出所属笔记本目录（如 `/doc/nb_AtmoDyn/`），立刻异步请求该目录下的 `index.json`。将里面文章标题列表渲染到左侧侧边栏。同时比对当前 `path`，为正在阅读的这一项自动挂载 `.active` 类名以实现高亮。

#### 任务D：右侧大纲生成（Article Outline）
- 无需任何外部 JSON 依赖。当正文 HTML 被塞入中央区域后，JS 在运行时实时扫描正文内的 `<h1>` 到 `<h6>` 标签。
- 提取其文本内容，并自动为对应的正文标题与右侧大纲建立对应的锚点映射（ID 绑定），在右侧侧边栏生成一个层级分明的大纲视图，支持点击平滑滚动。

### 3.页面设计与交互
整体设计与Hexo的Fluid主题差不多。导航栏保留的和aboutMe页面一致。支持黑白切换
打开时最上面是一张全宽的横图（每次在特定目录随机选取一张），图上居中显示内容：
文章大标题
作者name
icon xx年xx月xx日 上午/下午/晚上…
icon xx字  icon 阅读需xxmin  （相关信息写在markdown头部）

正文在一张居中的长卡片上，卡片最上方突破上面图片的底边界，可以突出来。
左侧：笔记本目录 | 中央：正文 | 右侧：大纲 （左右两侧内容不需要卡片）
大纲与目录需支持鼠标悬停动效，激活项需有明显但温润的高亮视觉提示，目录与outline应设计不同高亮颜色。
正文卡片外左下角有一个按钮（icon）可至顶部；正文卡片内最下面有前一篇后一篇按钮：
<(icon) xxx（标题）  xxx >
页面最底部（卡片外）：一行版权/转载声明。
